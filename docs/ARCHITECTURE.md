# 运行架构与 v0.3 扩展约定

更新：2026-11-03。当前运行规则仍为 v0.1；v0.3 完整设计基线见 [GAMEPLAY_V0.3_SPEC.md](GAMEPLAY_V0.3_SPEC.md)，尚未启用。`GAMEPLAY_V0.3_CURRENT.md` 和旧三选二 `GAMEPLAY_V0.3.md` 保留为历史讨论与方案。

## 生命周期

```text
load（注册主状态） → skill:init（注册技能） → game/reload（退出旧运行状态）

start / start_test → game/initialize → phase_1_load
                          ↓
                    game/phase_check
                          ↓
         rules/v01/phase + game/_tick_20
                          ↓
                    game/result/check
                          ↓
                   game/result/accept
                          ↓
              可选演出 → result/finish
                          ↓
                 game/settle → cleanup

abort / dev/reset_runtime / test/end_game_clear → game/cleanup
```

公开命令入口保留，调用方不再复制初始化或整套清理。`game/initialize` 处理玩家、世界、人数缩放、装备与任务；正式/测试入口只决定人数来源和测试附加物品。正在运行时拒绝再次 `start`，需要先 `abort`。结束演出中允许重开，共用清理会取消旧结果。

`game/cleanup` 可重复调用，不展示结果、不计算贡献、不发奖。它取消本包预约，清理参战/训练/小游戏玩家，清理世界临时实体，恢复开局前记录的自然回血与立即重生规则。地图永久 marker、长期成长及本局贡献记录保留。新局在统一初始化中重置本局贡献。

`game/reload` 在所有主/技能字段注册之后执行。有运行状态时安全退出；空闲重载不清理无关玩家的物品或游戏模式。不承诺重载后无缝继续半局。

## 状态所有权

| 状态 | 所有者 | 规则 |
|---|---|---|
| `$game in_game` | 对局生命周期 | 正式局为 1；空闲/结束演出为 0。保留此字段兼容已有技能条件 |
| `$game ie.mode` | 对局生命周期 | 0=无正式局，1=正式局，4=已接受结果且演出中；训练由玩家标记显式控制 |
| `$game ie.match_id` | 对局生命周期 | 清理时递增，持续跨局；不与临时清理一起归零 |
| `$game ie.humans` | 对局生命周期 | 对局开始时记录参战人数；转为母体或感染者时通过 `game/human/leave` 一次性递减，离线不会被当作转化 |
| `$game ie.players` / `$game ie.online` | 对局生命周期 | 开局人数快照与当前在线参战人数；有人离线时暂缓清剿结算，避免误判离线感染者 |
| 玩家 `ie.session` | 会话验证 | 进入正式/训练/小游戏时写入当前对局编号；重连时不匹配则退出旧状态 |
| `ie.participant` | 正式局 | 本局参战者；中途旁观者不会被正常退出流程清空物品 |
| `ie.active` | 玩家运行上下文 | 正式参战、明确训练、靶场或枪战参与者；空闲状态不启用全局技能 tick |
| `state.training` / `range.active` / `gs.player` | 各练习模块 | 显式授权运行，不用残留的职业 ID、死亡或感染状态推断训练 |
| `role.*`、职业 ID | 职业模块 | `_tag_*` 经 `role/clear` 替换旧职业，避免多职业标签共存 |
| 感染、孢化、复活字段 | 感染模块 | 自己推进玩家状态；不在 `infection/turn` 内直接决定整局胜负 |
| 设备进度/运输/撤离 | 任务与撤离模块 | 提交完成信息或撤离快照，最终结果经对局模块处理 |

Scoreboard/tag 是存储方式，不能取代这些写入约定。原版 team 承担友伤和显示；伪装母体仍可能与真实阵营不同，不能只靠 team 推断身份。

训练、开发身份切换、靶场和枪战的公开入口会拒绝覆盖正在运行的正式对局。管理员 `test/*` 中的场景构造仍可主动更改状态，应只在测试环境执行。

技能、枪械、天赋、感染和任务的周期性玩家更新只处理 `ie.active`；旁观者可以接收展示信息，但不应因其他人参赛而被清理道具、改写计时或传送。离线检查会对技能 tick 的玩家执行者进行约束，真实服务端回归还检查非参与者的物品及计时。

职业切换、玩家退出及感染转化在状态入口即时处理；非本职业物品和残留状态的兜底清理每 20 tick 执行一次，不再对所有非本职业玩家每 tick 重复清理。物品使用入口仍检查职业，不能依赖兜底清理作为权限判断。由于兜底是周期执行，异常注入的物品可能在背包中短暂保留最多约一秒。

手枪和 AK47 保留各自的 `tick` 入口，持枪状态、冷却、换弹进度和经验条更新统一由 `skill:weapon/common/tick_automatic` 实现；调用入口提供固定的武器和另一把枪名称。不同弹药、容量、开火和换弹实现仍分别归各枪所有。共享逻辑采用 [Minecraft 函数宏](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-20-2)，静态检查验证两组展开后的函数引用，服务端测试验证两枪开火和换弹。

霰弹枪使用 6 发弹匣和 9mm 弹药，狙击枪使用 5 发弹匣和专用弹药；换弹按库存逐发扣除，不允许弹药不足时凭空装满。狙击枪换走后仍推进冷却和拉栓，玩家退出时清除开镜与拉栓标签。

训练模式第一次进入时保存世界 `immediate_respawn` 原值，多名训练玩家共享这份快照；最后一名在线训练玩家退出、重载或切换到正式对局时恢复。玩家离线后重新进入训练时，会重新取得所需规则。正式对局仍保存和恢复自己的世界规则，不能覆盖训练前的快照。

断电和风暴由 `$blackout ie.event`、`$storm ie.event` 表示当前对局的事件状态，而不依赖各玩家是否在线。断电仅为参战上下文短时刷新黑暗，结束后自然消退，避免删除其他机制施加的黑暗；因此视觉效果最多会比事件结束晚约两秒消退。旧的玩家事件标签只在兼容清理中移除。

## 玩家临时状态清理

唯一字段清单：`tools/state_contract.json`。按身份、感染、技能、任务、UI 分类，同时列出本包修改的基础属性及需要重置的临时交互进度。技能 `init` 只注册目标和共享配置；具体玩家状态由 `player/reset` 清理，避免空闲重载改动旁观者。

修改字段后运行：

```powershell
python tools/generate_state.py
python tools/check.py
```

生成文件位于 `data/escape_island/function/player/reset/`，不要直接修改。运行入口 `player/reset` 协调各类字段、技能物品、经验条、视觉和基础属性恢复。

新增能力时必须说明：

1. 字段属于哪个模块，是否按玩家或按对局保存。
2. 开始值、进入状态和退出条件。
3. 是否需要加入临时状态清单；长期生涯与本局贡献不能加入。
4. 新实体和预约如何取消；世界实体加入 `game/reset_world`，预约加入 `game/cancel_schedules`。

设备由 `player/claim_entities` 写入创建者 `ie.owner` 和对局 `ie.session`；电池、机修陷阱与滑铲载具已接入。玩家编号 `ie.actor` 由递增分配器生成，保留跨局稳定，不加入临时清理清单。单人退出只清理属于自己的设备；完整世界退出清理所有运行实体。未加载区块中的旧设备在重新加载后按对局编号失效。

倒地和感染者死亡锚点同样归创建者所有；位置跟随、复活和清理按 `ie.owner` 匹配，不再通过最近距离猜测所属玩家。靠近或重叠的多名玩家不会互相删除锚点。

新增有归属的实体在本次同步生成时加 `ie.new`，由创建者调用 `player/claim_entities`，返回前移除暂存标签；以后统一使用 `ie.owned` 加 owner/session。不要在另一个 tick 中依赖 `ie.new`，也不要在永久地图 marker 上使用这些标签。

## 定时器与结算

个人抗性、母体伪装和登载扫描分别使用 `ie.resist_left`、`ie.disguise_left`、`ie.scan_left`，单位为 tick，由 `player/tick_timers` 每 tick 更新。它们不再使用无法保存玩家上下文的 `schedule`。

全感染演出使用 `ie.finish_left`，末期病毒使用 `ie.mutate_left`；都归当前对局所有。保留的环境预约在 `game/cancel_schedules` 统一取消。不要新增隐含保留 `@s` 的个人预约。

结果入口约定：

- `game/result/check` 在感染、设备和撤离更新后统一检查。
- 旧 `game/end_*` 只提供明确的结果请求，全部经 `result/accept` 取得结果锁。
- `result/accept` 只接受运行中的第一份结果，记录对局编号并停止模拟。
- `result/finish` 校验编号，表现与贡献汇总后执行共用清理；不再解除结果锁。
- `ie.settle_count` 仅用于诊断和回归，正常每场只增加一次。
- 清剿检查会等待未完成的孢化，并要求存在仍存活的幸存者；候机者仍可计入可能生还者。
- 全感染判定使用对局内幸存者计数，不把离线当作转化；清剿判定在参战者离线时暂缓。若玩家永久离线，清剿会一直等待，其他结局和对局时限仍可推进；这是当前保守策略，尚未实现断线超时或投降规则。
- 母体未被记录为死亡但暂时离线时，倒下的感染者等待其重新连接；不会因在线选择器找不到母体而永久死亡。
- 伪装认证中断只驱离认证对象，不再清空其他幸存者的候机状态。

v0.1 的阶段时间线已隔离到 `game/rules/v01/phase`。v0.3 开发应新增独立规则调度，在 `game/phase_check` 按 `ie.ruleset` 分发；不要把新旧阶段条件堆叠到同一时间线。当前初始化固定 `ie.ruleset=1`，不提供一个尚未实现的 v0.3 启动选项。

v0.3 R1 以供电、信号塔和直升机为主线，船与潜艇按人数抽取，W-7 是低概率隐藏调查链。完整规格已定义人数配置、时限、胜利门槛、状态变化与同刻事件顺序；主要参数见 `GAMEPLAY_V0.3_RULES.json`，这些仍是待测试的设计初值，不能当作现有运行行为。实现时按完整规格 §20 划分状态所有权，按 §17 统一提交撤离与结果，避免路线各自结算；新旧玩法继续隔离，不在基础重构中提前启用。

信号塔每秒只统计手持线缆且处于活动对局的幸存者，每人归属最近的未完成塔；工程师数量与修理人数使用同一归属。团队基础倍率按 1/2/3/4 人分别取 100/125/140/150%，每名正在修理的工程师加 25 个百分点，附近有效电池再加 25 个百分点，合计封顶当前四人倍率；发电机与母体光环随后作为独立乘子。此规则是对既有平衡文档中“个人加成、受团队上限约束”的明确实现，实际多人平衡仍需玩家测试。船坞职业和电池加成只在至少一名合格幸存者正在修理时生效，非参赛者不参与增益或压制。

## 验证

统一离线检查：

```powershell
python tools/check.py
```

当前包含：生成清单一致性、JSON/元信息解析、函数/标签/advancement 奖励引用、同级依赖、预约取消覆盖，以及读取实际函数文件的生命周期回归和模块约束检查。

状态回归覆盖个人计时、属性恢复、重复结算、旧回调、新旧会话、训练/枪战切换、空闲重载、旁观者、连续两局初始化，以及设备归属和旧区块设备失效。`tests/mcfunction_vm.py` 是有明确范围的状态执行器：世界、物品、实体和视觉命令使用替代实现，未支持的控制分支报错。**它不是 Minecraft 命令编译器，不能证明真实多人玩法和实体交互正常。**

游戏内手动冒烟测试：

```mcfunction
/reload
/function escape_island:test/regression_lifecycle
```

此测试会清理测试状态；拒绝在正式局中运行。查看 `[PASS]` / `[FAIL]` 输出，再做：四人正常对局、全感染演出时重开、感染期中止与重载、两名玩家错开治疗、候机转化、母体死亡后清场、正式/训练/枪战来回切换。

性能测试使用真实服务端 `/perf start` 及其报告。已减少空闲 UI/技能扫描并合并每秒玩家更新，但没有在未测量的情况下承诺 TPS 提升。

## 工具与依赖

同级 `FastMotion` 提供 `motion:apply_scoreboard`，引用检查会实际读取该包；`dc_v2.1.0` 保留为既有外部依赖。未复制库文件或添加同名 shim。

更换 checkout 或电脑后执行 `python tools/configure_editor.py`，重新生成 Spyglass 的本机绝对依赖 URI。[Spyglass 的依赖配置定义](https://raw.githubusercontent.com/SpyglassMC/Spyglass/main/packages/core/src/service/Config.ts)要求绝对文件路径，因此不假设相对路径受到支持。

`pack.mcmeta` 现明确声明 `[94, 1]` 到 `[94, 1]`，目标为 [Minecraft Java 1.21.11 的数据包版本 94.1](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21-11)。[官方元信息格式说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21-9)定义了二元整数数组的主/次版本写法；不再宣称支持未知未来版本。

Animated Java 仍为生成资产，未进行手工重写。其导出的 `global/on_load` 存在无条件自调用，不能直接挂到 load 标签：`escape_island:compat/animated_java_load` 初始化公共状态和直升机动画目标，tick 标签接入 `animated_java:global/on_tick`。模型重新导出后应复核兼容层和真实动画播放。枪械射线、职业技能表现和地图资产保持原有模块，后续通过已有明确入口接入新任务与强化。

隔离的真实原版服务端验收及复现方法见 [ENGINE_ACCEPTANCE.md](ENGINE_ACCEPTANCE.md)。正式开局的地图前置检查只能检查已加载区块，配置要求见 [MAP_GUIDE.md](MAP_GUIDE.md)。
